Write an interface to the Orca QM engine equivalent to the interface to turbomole found in lefqm/turbomole.py. The Orca binary can be found in /usr/local/bin/orca_6_1_1_linux_x86-64_shared_openmpi418/orca. Do not confuse it with /usr/bin/orca. There should be one function called orca_calculate_shieldings that takes a molecule, a path to the Orca binary, the number of cores to use, and a directory to run the calculation in. The function should return the shieldings constansts as a list of floats in the same order as the input order of the atoms in the input molecule.

An Orca input file can be found in /tmp/tmp.5PsDmlkqdQ/input.inp. Use this input file as a template and make the parts that control molecular charge and molecular geometry variables. /tmp/tmp.5PsDmlkqdQ/orca.log is the output running an Orca calculation using that input file. Use this file to implement checks that the calculation ran correctly and to implement extraction of the shielding constants.

Before doing anything check if the Orca binary is available and return a RuntimeError if it isn't. If no run directory was specified, create a temporary directory. Then construct the input file and the log file. After this call the Orca binary and give it the path to the input file and capture the calls standard output in the log file. After the Orca command has stopped executing check that the calculation succeeded. If it hasn't throw a RuntimeError with an appropriate error message. If the calculation has succeeded extract the shieldings constants from the logfile and return them as a list of floats. Make sure to clean up the temporary directory if it exists before returning the shielding constants.

Write tests for the functions created and add these tests to the CommandlineCalculationTests test suite. Overwrite the test file tests/data/TFA_shieldings.sdf with a version of this molecule with shieldings calculated by Orca and write the test so that these shieldings are tested against the newly calculated ones.
